# M0.4 database layer: baseline

First implementation of `src/db`, so there is no "before". Later changes to the database layer compare against these numbers, measured the same way.

## Setup

| | |
|---|---|
| Date | 2026-10-27 |
| Machine | AMD Ryzen 5 1600 (6 cores), 16 GiB RAM, Linux 6.12 (Debian 13), VM |
| Disk | ext4 on `/dev/sda1` (the repository's disk, not tmpfs) |
| Bun | 1.4.4 (bundled SQLite 3.53.4) |
| Commit | `task/M0.4-db-layer` |

## Method

`bun test/db/bench.ts --dir .upstream/bench` after `bun run upstream:prepare`, run with `nice -n 10` while the host was otherwise idle. Each run copies upstream's `tests/data` into a new scratch directory, opens it with `Databases.open` (upstream's pragmas: WAL, `synchronous=NORMAL`) and removes it afterwards.

- **Open:** `Databases.open` on a fresh copy, which opens `data.db` and `auxiliary.db` and applies the pragmas on each. Median of 20 copies.
- **Insert:** `app.db().insert("bench", {id, title, n}).execute()` into a three-column table with a text primary key. "Outside a transaction" is one implicit transaction per row (2,000 rows); "inside" is 20,000 rows in one `runInTransaction`.
- **Select:** `app.db().select("id", "title", "n").from("bench").where(new HashExp({id})).limit(1).one()`, 20,000 lookups by primary key, outside and inside one transaction. Each call builds the query (dbx SQL text, placeholder processing) and runs it on the cached statement.
- **10,000-row select:** `select(...).from("bench").limit(10_000).all()` returning row objects. Median of 20.

Both concurrent and nonconcurrent builders run on the main-thread connection (M0.6 decides D8).

## Results

Two runs; the second in parentheses.

| Measurement | Result |
|---|---|
| Open `data.db` + `auxiliary.db` (median of 20) | 0.72 ms (0.73 ms) |
| Single-row insert, outside a transaction | 20,069 ops/s (18,050) |
| Single-row insert, inside one transaction | 132,829 ops/s (102,503) |
| Single-row select by id, outside a transaction | 100,481 ops/s (110,372) |
| Single-row select by id, inside one transaction | 170,005 ops/s (159,148) |
| 10,000-row select (median of 20) | 2.71 ms (2.86 ms) |

## Notes

- Inserts outside a transaction are bounded by the WAL commit per row (`synchronous=NORMAL` does not fsync on each commit, but each commit still writes a WAL frame and takes the write lock).
- Selects outside a transaction start and end an implicit read transaction per statement, and `app.db()` creates the routing builder on each call, as upstream's `DB()` does.
