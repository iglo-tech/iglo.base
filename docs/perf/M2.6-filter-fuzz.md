## Detection

A clean run only counts if the fuzzer can fail. Multi-match was deliberately removed for `!=` in `src/search/filter.ts`, then restored: 1,500 cases gave 4 distinct failures, each shrunk to one condition (`@collection.users.name != ""`). A separate 30,000-case exploratory run, which also required the same order for every list and equal item bodies, found no difference.

## Method

- **Data:** upstream's fixture on one copy per server. Upstream's API sets four list rules first (`demo1`, `demo2`, `numeric_id_view`, `view2`), giving relation, auth-relation, header and `@collection` rules beside the fixture's null, `""` and field rules. It also creates `fuzz_items` and `fuzz_tags` (`test/differential/fuzz/data.ts`), because the fixture has no stored `%`, `_`, `\` or non-ASCII text, no JSON scalars, no large or fractional numbers, no dangling relation, and no data behind a unique single back-relation.
- **Ambiguous order:** ids are compared in order only when the sort has an `id` or `@rowid` term and no earlier term can be multi-valued for a record. Otherwise a list holding every match is compared as a set, and a partial page by its size.
- **Clock:** `@second` and `@minute` appear only in comparisons that hold at any instant (`@second < 60`). Other macros and current-time `strftime` are marked time-dependent, and a difference on such a case is retried once; neither seed needed a retry. `strftime` of the current time uses formats no finer than a day, because finer ones race with `@now` inside one server: one early run reported `strftime("%Y-%m-%d %H:%M:%f") <= @now`, which flipped in both directions and is not a server difference.
- **Throttle:** upstream's randomized list throttle applies on both servers and is part of the durations above.
