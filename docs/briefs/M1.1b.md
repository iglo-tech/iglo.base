Task M1.1b: Go regexp matching
Goal: port Go's regexp package (go1.27.2) on top of the M1.1a parser, with Go's compiler, program and NFA matcher, so that iglo.base matches any pattern exactly as upstream does (RE2 semantics, leftmost-first, linear time) and later tasks use it for user patterns (text and password field `pattern`) and for upstream's constant patterns.
Read first: AGENTS.md, docs/design/12-work-plan.md (task M1.1b, Rules for workers), docs/briefs/M1.1a.md, and the M1.1a code: src/tools/regexp/syntax/ and src/tools/unicode/.
Upstream: Go standard library at go1.27.2 (shallow-clone https://github.com/golang/go at tag go1.27.2 read-only into `.upstream/deps/` in your worktree, git-ignored): src/regexp/syntax/compile.go, prog.go and simplify.go (Compile simplifies first); src/regexp/regexp.go, exec.go (the NFA, pike VM) and the parts of backtrack.go and onepass.go that change results (none should; read them to confirm). Tests: src/regexp/all_test.go, find_test.go, exec_test.go (the RE2 search test data in testdata/, re2-search.txt and re2-exhaustive.txt.bz2 if feasible) and syntax/prog_test.go, simplify_test.go. PocketBase v0.41.0 (.upstream/pocketbase or /home/t3-code/upstream/pocketbase) for how upstream calls regexp: core/field_text.go, core/field_password.go (MatchString of a user pattern), core/validators/string.go (Compile as a validator).
Owns: src/tools/regexp/ (regexp.ts with Regexp, compile, mustCompile, matchString, match on bytes, quoteMeta, and the methods listed below; exec.ts; syntax/compile.ts, syntax/prog.ts, syntax/simplify.ts), test/tools/regexp/, docs/perf/regexp.md.
Depends on: M1.1a (merged).
Acceptance:
  - API, with Go names in camelCase: compile, mustCompile, compilePOSIX only if cheap, matchString, match, quoteMeta; Regexp methods matchString, match, findString, findStringIndex, findStringSubmatch, findStringSubmatchIndex, findAllString, findAllStringSubmatch, findAllStringIndex, replaceAllString (with Go's $1, ${name} expansion), replaceAllLiteralString, replaceAllStringFunc, split, numSubexp, subexpNames, subexpIndex, string, literalPrefix, longest. Inputs are JS strings; indexes are Go byte offsets of the UTF-8 encoding unless you document otherwise. Pick one and keep it consistent; byte offsets are the safer choice for porting upstream callers.
  - Matching is Go's: the M1.1a parse, Simplify, compile to Go's Prog, and run Go's NFA. Do not translate patterns into JS RegExp. Results must equal Go's for every ported test table case: all_test.go and find_test.go cases for the ported functions, the RE2 search tests from testdata/ (all of re2-search.txt; re2-exhaustive.txt.bz2 too if it runs in reasonable time, otherwise a deterministic sample with the reason in the PR), prog_test.go dumps, simplify_test.go.
  - Invalid UTF-8 in the input string (lone surrogates) is read as Go reads invalid bytes: one U+FFFD-width step per invalid byte. Document how a JS string with lone surrogates maps to bytes.
  - Linear time: a test runs a classic catastrophic pattern for backtracking engines, such as (a+)+$ and (a|aa)*b, against a 30-character and a 3,000-character input, and checks that time grows roughly linearly (generous bounds; no flaky timing assertions under 50 ms).
  - Measurements in docs/perf/regexp.md: matchString time for upstream-like patterns (an email-like pattern, `^\w+$`, `^[a-z0-9]{15}$`, a 50-alternation pattern) on 16-byte, 1 KiB and 64 KiB inputs, compiled once, with the machine and Bun version. If the NFA alone is too slow for the 1 KiB case (more than about 1 ms per match), port onepass.go and/or backtrack.go as Go does, and say which in the PR.
  - A test:reference test (test/differential/) checks a sample of at least 30 pattern-input pairs through the upstream binary: a text field with `pattern` on a fresh-install collection, a record create with each value, and the same accept or reject decision in iglo.base's matchString. Include Unicode classes, case folding (?i), \b, anchors, multiline flags, empty alternatives and invalid UTF-8-free inputs with astral characters.
  - `bun run check` and `bun run test:reference` pass locally and in CI.
Out of scope: changing M1.1/M1.1a callers (list.ts, inflector.ts keep their hand-translated JS RegExp; later tasks may switch them); text and password fields (M1.4, M1.5); validation rules (M1.1c); any other module.
Measurements: docs/perf/regexp.md as above (regexp runs on the record write path through field patterns).
Notes from the lead:
  - Decided by the lead (logged in docs/status.md): iglo.base matches Go regexps with a port of Go's own matcher, not with JS RegExp. Reasons: user patterns must accept exactly what upstream accepts, and RE2 is linear time while JS RegExp backtracks, so a translated pattern could be made to run for an exponential time by a record value.
  - Go's regexp is BSD-3-Clause; extend the Go notice in LICENSE (added by M1.1a) with the new translated paths.
  - Header comment in each file names its Go source file.
  - Branch: task/M1.1b-regexp. PR title: "M1.1b: Go regexp matching".
