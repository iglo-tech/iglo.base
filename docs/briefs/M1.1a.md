Task M1.1a: Go regexp/syntax parser and RandomStringByRegex
Goal: port the parser of Go's regexp/syntax (the version in the Go toolchain upstream v0.41.0 was built with, go1.27.2) to TypeScript, and port upstream's security.RandomStringByRegex on top of it, so that any pattern is accepted or rejected exactly as upstream does, with Go's error text, and generated strings come from the same parse tree.
Read first: AGENTS.md, docs/design/12-work-plan.md (task M1.1a, Rules for workers), docs/briefs/M1.1.md, and the M1.1 code it builds on: src/tools/security/ and src/tools/types/go-json.ts (Go string and rune helpers).
Upstream (v0.41.0, .upstream/pocketbase after `bun run upstream:prepare`, or /home/t3-code/upstream/pocketbase):
  - tools/security/random_by_regex.go and random_by_regex_test.go.
  - core/field_text.go: where the pattern and its error reach users (validation_invalid_autogenerate_pattern with err.Error(), and the autogenerate path). Read only, for how the errors surface; M1.4 ports the field.
  Go standard library at go1.27.2 (shallow-clone https://github.com/golang/go at tag go1.27.2 read-only into `.upstream/deps/` in your worktree, git-ignored, as M1.1 did): src/regexp/syntax/parse.go, perl_groups.go, regexp.go (Op values, Flags, the String form), op_string.go, doc.go, and their tests parse_test.go and the parts of syntax tests that check parse trees and errors; src/unicode (tables.go, letter.go: the Categories, Scripts, CaseOrbit and fold tables that parse.go uses for \p{...} and case folding); utf8 behavior for string(rune) of invalid runes and surrogates (U+FFFD).
Owns: src/tools/regexp/syntax/ (the parser, Op and Flags with Go's numeric values, the parse tree, Go's Error type and text), the Unicode tables it needs (generated from Go's unicode/tables.go by a committed generator script under scripts/, with the generated file committed and a header naming the Go version), src/tools/security/random-by-regex.ts, test/tools/regexp/, test/tools/security/random-by-regex.test.ts, and the Go notice in LICENSE.
Depends on: M1.1 (merged).
Acceptance:
  - Go's parse_test.go tables are ported as data-driven bun tests: every parse-tree dump case (Perl flags, POSIX flags, the other flag sets, foldcase and literal tests), every invalid-regexp case with its flags, and every error-text case. A case that cannot apply in TS is listed in the PR body with a reason. Compare parse trees through a port of the test's dump format, so a tree is checked node by node.
  - parse(pattern, flags) returns the same tree as Go for every case, including Op numeric values, Min/Max, flags on nodes, rune ranges after Go's class cleanup, negated classes (up to unicode.MaxRune, as Go does), and capture names and indexes. It throws Go's error with the same Error() text ("error parsing regexp: <code>: `<expr>`") for the same patterns, including the 1000 repeat limit, nesting depth, and invalid UTF-8.
  - randomStringByRegex(pattern, flags = Perl) follows random_by_regex.go: the same op switch (and "unsupported pattern operator %d" with Go's Op number for anchors, word boundaries and empty matches, including the empty pattern), defaultMaxRepeat 6, the anyCharNotNL pairs, the cumulative range selection, and string(rune) semantics (a surrogate or out-of-range rune writes U+FFFD). Secure randomness (crypto.getRandomValues, unbiased like crypto/rand.Int).
  - The ported random_by_regex_test.go cases pass. Each generated string must match its pattern; use a JS RegExp equivalent for the tested patterns and say so in the test.
  - Error texts checked against the upstream binary for a sample of at least 15 invalid patterns (missing paren, bad repeat, repeat over 1000, bad escape, bad class range, invalid named capture, bad Perl flag, \C, \z with POSIX…): start upstream on a throwaway pb_data from a fresh install, create a collection with a text field whose autogeneratePattern is each pattern, and compare the validation message with iglo.base's error text. Commit this as a `test:reference` test in test/differential/ (it starts upstream through the existing helpers; no network beyond `upstream:prepare`).
  - `bun run check` and `bun run test:reference` pass locally and in CI.
Out of scope: regexp matching (compiling the tree to an engine, or translating it into a JS RegExp) — M1.4 decides how text field `pattern` values are matched with Go semantics and may build on this tree; syntax.Simplify and the compiler (prog.go, compile.go), unless the parser needs a piece of them; the text field itself (M1.4); any change to other modules, or to M1.1 code beyond adding the export that M1.1a needs.
Measurements: none (no db, filter, realtime or file handling change).
Notes from the lead:
  - Decided by the lead (logged in docs/status.md): Go's regexp/syntax and unicode packages are BSD-3-Clause (Copyright 2009 The Go Authors), compatible with MIT. Add Go's notice to LICENSE next to dbx's, naming the translated paths.
  - Generate the Unicode tables from Go's own tables.go, not from JS \p{...}, because JS engines may use a different Unicode version than go1.27.2. Generate only what parse.go needs. Keep the generator small and its output deterministic.
  - Keep module and function names close to Go's for side-by-side review, with a header comment naming each upstream file.
  - The flags argument of randomStringByRegex is a bitmask of the ported Flags, as Go's optFlags (OR of the given flags; Perl when none are given).
  - Branch: task/M1.1a-regexp-syntax. PR title: "M1.1a: Go regexp/syntax parser and RandomStringByRegex".
