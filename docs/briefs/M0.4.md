# Brief M0.4

Written by the chief of staff on 2026-10-27 from the work plan's template.

```text
Task M0.4: Database layer (connections, pragmas, transactions, busy retry, dbx subset builder)
Goal: a src/db module that opens a pb_data's data.db and auxiliary.db with upstream's pragmas through bun:sqlite, runs queries and transactions with upstream's busy retry, and builds SQL with a port of the dbx subset that produces upstream's SQL text, so M1 and M2 can build on it.
Read first: AGENTS.md, docs/design/02-architecture.md (Module layout, db/), docs/design/03-data-compatibility.md, docs/design/05-rules-and-filters.md (the dbx paragraph), docs/design/10-decisions.md (D8, D9), docs/design/12-work-plan.md (Shared contracts, Rules for workers), and the src/app/ module merged by M0.3.
Upstream (v0.41.0, .upstream/pocketbase after `bun run upstream:prepare`, or /home/t3-code/upstream/pocketbase):
  - core/db_connect.go (the pragma string, order matters: busy_timeout first; _defensive=1), core/db_connect_nodefaultdriver.go (read only, for context).
  - core/db_builder.go (dualDBBuilder: concurrent vs nonconcurrent routing), core/db_retry.go (+ db_retry_test.go), core/db_tx.go (+ db_tx_test.go; drop hook and event expectations), core/db_table.go (+ db_table_test.go: TableColumns, TableInfo, TableIndexes, HasTable, DeleteTable, DeleteView, Vacuum), core/db_model.go (+ db_model_test.go), core/db.go (+ db_test.go): only the generic model query, insert, update and delete SQL paths, without hooks, events or validation (records are M1.8, validation belongs to the fields and collections tasks).
  - core/base.go: initDataDB, initAuxDB, DB/ConcurrentDB/NonconcurrentDB/AuxDB*, the connection defaults (DefaultDataMaxOpenConns etc., DefaultQueryTimeout) and how ResetBootstrapState closes them.
  - pocketbase/dbx v1.13.0 (the pinned version from go.mod; its source is checked out at /home/t3-code/upstream/dbx, tag v1.13.0, commit 0d62a5f; read only. The upstream forge is https://ganigeorgiev.com/git/pocketbase/dbx): builder.go, builder_standard.go, builder_sqlite.go, expression.go, query_builder.go, select.go, query.go, tx.go, model_query.go, struct.go, and their *_test.go files. Port only the subset pocketbase calls (grep the pocketbase tree for dbx. uses): Select/From/Where/AndWhere/OrWhere/Join/LeftJoin/InnerJoin/OrderBy/AndOrderBy/GroupBy/Having/Limit/Offset/Distinct/Union, Insert/Update/Delete/Upsert as used, CreateTable/DropTable/RenameTable/AddColumn/DropColumn/CreateIndex/CreateUniqueIndex/DropIndex as used, NewExp/HashExp/Not/And/Or/In/NotIn/Like/NotLike/OrLike/Exists/NotExists/Between/NotBetween, named {:param} placeholders, quoting of table and column names ({{table}}, [[column]]), and Params. Skip the MySQL, PostgreSQL, MSSQL and OCI builders.
Owns: src/db/ (connect, builder, expressions, query, transactions, retry, tables, model helpers), test/db/, the db/ line of the Module layout in docs/design/02-architecture.md, docs/perf/M0.4-db-layer.md (new), and small additions to src/app/app.ts only if a type for the database handles is needed there (do not wire the databases into `serve`: that happens in M1.2 together with the system migrations).
Depends on: M0.1, M0.3 (merged).
Acceptance:
  - Ported dbx tables pass for the sqlite/standard builder: the expression, select, query builder and builder tests (SQL text and params identical to upstream's expectations, sqlite quoting).
  - Ported core tables pass: db_retry_test, db_tx_test (without hook expectations), db_table_test, db_model_test, and the db_test cases that don't need records or collections (list the rest in the PR, naming the owning task).
  - Opening a temporary copy of upstream's tests/data (data.db and auxiliary.db) applies upstream's pragmas: reading them back (journal_mode, busy_timeout, synchronous, foreign_keys, temp_store, cache_size, journal_size_limit) gives the same values as upstream's connection. Queries on the copy return the fixture's rows. upstream's tests/data itself is never written; tests copy it to a temp dir first.
  - The data contract holds: after iglo.base opens, writes through a transaction and closes a temp copy, the upstream v0.41.0 binary starts on that copy (`bun run test:reference` case) and reports nothing pending. Nothing iglo-specific is created in either file.
  - Busy retry: a write blocked by another connection's lock is retried as upstream's db_retry.go does (attempts and backoff); tested with an injected clock or two real connections, never by long sleeps.
  - Transactions: nested RunInTransaction reuses the outer transaction like upstream; an error or throw rolls back; a commit failure is reported.
  - `bun run check` and `bun run test:reference` pass locally and in CI.
Out of scope: the read worker pool and --queryTimeout enforcement (spike M0.6 decides D8; for now both builders run on the main-thread connection behind the same concurrent/nonconcurrent API so M0.6 can swap the implementation), system migrations and bootstrap wiring (M1.2), records and the record query builder (M1.8), the filter resolver (M2.1, M2.2), backups (M5.3).
Measurements: docs/perf/M0.4-db-layer.md with baseline numbers (first implementation, so there is no "before"): open time of both fixture files, single-row insert and select throughput in and out of a transaction, and a 10,000-row select, with machine, Bun version and method. Later tasks compare against it.
Notes from the lead:
  - bun:sqlite may not expose SQLITE_DBCONFIG_DEFENSIVE (_defensive=1). If it can't be set, say so in the PR and in docs/design/03-data-compatibility.md; do not add a native addon.
  - Keep dbx names (SelectQuery, Expression, HashExp, Params…) in camelCase TypeScript. Each file names its upstream file (dbx or core) in the header.
  - No process-global state: connections are created by an open function and passed in by the caller.
```
