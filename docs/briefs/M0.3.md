# Brief M0.3

```text
Task M0.3: Shared contracts (router, request event, API errors, app context)
Goal: replace M0.1's temporary dispatch with a port of upstream's router, request event and API error helpers, plus the app context and clock every later module receives, so that routing, error bodies and base middleware order behave like upstream v0.41.0.
Read first: AGENTS.md, docs/design/02-architecture.md (Process model, Module layout, Configuration), docs/design/04-api-compatibility.md, docs/design/01-scope.md (no extension surface), docs/design/12-work-plan.md (Shared contracts, Rules for workers), docs/briefs/M0.1.md and the code M0.1 merged in src/.
Upstream (v0.41.0, .upstream/pocketbase after `bun run upstream:prepare`, or /home/t3-code/upstream/pocketbase):
  - tools/router: router.go (BuildMux, ErrorHandler, ResponseWriter status/written tracking), group.go, route.go, error.go (ApiError, New*Error helpers, message normalization, validation error data), event.go (request event: JSON/String/HTML/NoContent/Redirect/Stream helpers, RealIP, BindBody, Get/Set), rereadable_read_closer.go, buffer_with_file.go, unmarshal_request_data.go; and their *_test.go files.
  - core/event_request.go (RequestEvent: auth placeholder, HasSuperuserAuth, RequestInfo shape) and core/event_request_test.go where it does not need records or collections.
  - apis/base.go: NewRouter (default middleware order, API route group order), safeRedirectPath; Static only as the GET /{path...} registration that returns router.ErrFileNotFound when nothing is served (file serving is M5.7).
  - apis/middlewares.go: the middleware ids and priorities, panicRecover and securityHeaders (port both). The other default middlewares (activityLogger M5.5, rateLimit M4.8, loadAuthToken M2.3, superuserIPsWhitelist M2.3, BodyLimit M5.7) get their slot in the ordered chain as no-op placeholders that name their task.
  - core/app.go: interfaces only, to decide what the app context carries now.
  - Go's net/http ServeMux (1.22+ patterns) is what BuildMux relies on; the client-visible behavior must match it: {name} and {path...} wildcards, most-specific-pattern precedence, GET also serving HEAD, path cleaning redirects (301 for /a/../b, //x), trailing slash handling, escaped path segments.
Owns: src/server/ (router.ts, group.ts, route.ts, event.ts, error.ts and the body helpers, replacing the temporary dispatch in serve.ts), src/apis/base.ts, src/apis/health.ts (use the event), src/middlewares/panic-recover.ts and security-headers.ts plus the placeholder slots, a new src/app/ module (app context type and clock), test/server/, test/apis/ updates, small test/differential/ cases, the Module layout in docs/design/02-architecture.md (add src/app/).
Depends on: M0.1, M0.2 (merged).
Acceptance:
  - Ported upstream tables pass: router_test, group_test, route_test, error_test, event_test (cases that need records, files or the app's DB are listed in the PR as moved to their owning task), rereadable_read_closer_test, buffer_with_file_test, unmarshal_request_data_test. They are tests of internal modules and are allowed as such, because the router, event and error helpers are shared contracts (work plan); HTTP-level behavior is also tested through the compiled executable.
  - Through the compiled executable: GET/HEAD /api/health keep M0.1's behavior and now carry upstream's security headers; unknown GET → "File not found." 404, other methods → "The requested resource wasn't found." 404; a panic inside a handler returns upstream's 500 body (test via an internal test route only in test code, never shipped).
  - New differential smoke cases in test/differential/ (run by `bun run test:reference`) compare iglo.base and the upstream binary for: /api/health (GET, HEAD), unknown GET and POST, path cleaning redirects (/api/../api/health, //api/health, /api/health/.), an escaped segment (/api%2Fhealth), and compare status, body and the security headers.
  - No process-global state: the router, app context and clock are created per server instance and passed down. No public registration API, hooks, plugin surface or event bus: routes and middlewares are bound in src/apis/base.ts only (AGENTS.md "No extension surface"). Middleware ids/priorities are internal ordering, not an extension point.
  - `bun run check` and `bun run test:reference` pass locally and in CI.
Out of scope: the database layer (M0.4), real auth loading and superuser IP checks (M2.3), rate limiting (M4.8), activity logging (M5.5), body limit, CORS, gzip, static files, trusted proxy (M5.7), realtime streams beyond the event helper (M5.1), the differential harness and scenario format (M0.5).
Measurements: none (no db, filter, realtime or file handling change).
Notes from the lead:
  - The app context carries only what exists now (data dir, dev flag, query timeout, encryption env name, clock, an error logger). Later tasks add fields through their own change; do not pre-design settings or DB handles.
  - The clock is injectable (now()) so later tests never sleep.
  - Keep names close to upstream (RequestEvent, ApiError, newNotFoundError …) and name the upstream file in each file's header.
```
