```text
Task M3.6: Data round-trip suite
Goal: a suite proves the data contract end to end: upstream v0.41.0 → iglo.base → upstream on the same `pb_data`, on the fixture, a fresh install and generated data, with results equal to what upstream alone produces.
Read first: AGENTS.md, docs/design/03-data-compatibility.md (all of it, Verification above all), docs/design/09-port-plan.md (Data round-trip suite), docs/design/12-work-plan.md (M3.6, Rules for workers), test/differential/harness/, test/differential/records-write/, test/differential/files/, test/support/.
Upstream (v0.41.0): the binary is the reference; read source only to explain a difference.
Owns: test/differential/roundtrip/ (new), a `test:roundtrip:large` package.json script, the Verification section of 03-data-compatibility.md and the round-trip paragraph of 09-port-plan.md.
Depends on: M3.1, M3.2 (merged).
Acceptance:
  - Each run has three legs on one pb_data: (1) upstream runs a write-heavy scenario through the API and stops; (2) iglo.base starts on the result, verifies the data through the API with responses equal to upstream's, runs the same scenario and stops; (3) upstream starts again, reads back everything iglo.base wrote through the API, and a further write works.
  - A control run does the same three legs with upstream alone. Leg 3's result is compared with the control after normalizing generated values (ids, timestamps, tokens, password hashes, random file-name suffixes): `sqlite_schema` of both databases byte for byte, `PRAGMA integrity_check`, `_migrations`, `_collections`, `_params`, every row of every table, and `storage/` (names, file bytes, `.attrs`, thumbs). Read those from a copy of pb_data, after the servers stop. `sqlite_stat4` is the one known difference (M1.2) and no other table, column, index, trigger, `_params` or `_migrations` row may appear.
  - The scenario covers every field type with values at their edges (json with integer-like keys, duplicate-free large integers and exact bytes; decimals; dates; empty and null values; multi-select and multi-relation; geoPoint; editor; autodate; password), base, auth and view collections, schema changes (add, rename and drop a field; rename a collection; add and drop an index; rule changes), updates with `+`/`-` modifiers, cascade delete, file upload, replace and delete with thumbs generated, batch, settings saved encrypted and plain, superusers, auth origins and tokens issued by one server used on the other (a token signed before a leg stays valid after it).
  - Fixtures: the vendored upstream fixture, a fresh v0.41.0 install, and a generated dataset. The generated dataset is at least 20,000 records through the API; it runs as `bun run test:roundtrip:large`, not in `bun run test:reference`, and must stay under about 1 GiB of disk. The other two run in `bun run test:reference` and add at most a few minutes.
  - A self-test proves the comparison catches a difference: a deliberately altered copy (an extra index, a changed `.attrs`, a changed row) fails it.
  - `bun run check`, `bun run test:reference` and `bun run test:roundtrip:large` pass locally (D25).
Out of scope: logs (M5.5; check only that `auxiliary.db` written by upstream stays intact and opens), OTP and MFA flows (M4.2), OAuth2 (M4.5), backups (M5.3), S3 (M5.4), crash tests (M5.9).
Notes from the lead:
  - A real difference in stored data is a bug: this is the task's main result. Fix it in the owning module in its own commit named in the PR, with a differential case, if it is small and clear. Otherwise stop and report it in the PR; the lead decides. Do not normalize a difference away: every normalization rule names why the value is generated.
  - Keep each ordering deterministic and add no sleeps; use the existing harness for starting and stopping servers, and stop each server cleanly before the next leg.
  - The host has limited memory and disk: run commands one after the other, never in parallel; delete generated data; never write into tracked fixtures. Never run `docker system df` or broad recursive du/find scans (host rules in /home/t3-code/AGENTS.md).
  - Branch: task/M3.6-roundtrip. PR title: "M3.6: Data round-trip suite".
  - There is no time limit; finish the task. Stop early only for a real blocker (a design conflict the lead must decide, or a usage/rate-limit error), and describe it in the PR and your reply.
```
