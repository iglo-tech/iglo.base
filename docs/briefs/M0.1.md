Task M0.1: Project skeleton
Goal: a Bun + TypeScript project whose compiled executable parses upstream's CLI, rejects the removed extension flags and the update command, and serves GET /api/health like upstream for a guest.
Read first: AGENTS.md, docs/design/README.md, docs/design/01-scope.md (Removed sections, CLI row), docs/design/02-architecture.md (Shared ground, Module layout, Configuration, Data directory), docs/design/10-decisions.md (D3, D5, D11, D19), docs/design/12-work-plan.md (M0 rows, Rules for workers, Shared contracts).
Upstream (v0.41.0, /home/t3-code/upstream/pocketbase):
  - pocketbase.go (root command, eagerParseFlags: --dir, --encryptionEnv, --dev, --queryTimeout; default data dir next to the executable; skipBootstrap/unknown-flag handling; Version)
  - cmd/serve.go (serve [domain(s)], --http/--https defaults with and without domains, --origins)
  - examples/base/main.go (the prebuilt binary's flags: --publicDir and --indexFallback are kept; --hooksDir, --hooksWatch, --hooksPool, --migrationsDir, --automigrate are removed)
  - apis/health.go (guest response only)
  - apis/serve.go (only for the startup banner text and the http/https address handling; not the rest)
Owns: package.json, bun.lock, tsconfig.json, oxlint and oxfmt config, the pre-commit format hook and its install script, .github/workflows/ (CI), renovate.json, .gitignore, src/cli/, src/apis/health.ts, a minimal src/server/serve.ts bootstrap, test/cli/ and test/apis/health tests, the "Verification" section of AGENTS.md, the CLI facts in docs/design/01-scope.md and 02-architecture.md if the exact error text or behavior needs recording.
Depends on: none.
Acceptance:
  - `bun install --frozen-lockfile`, lint (oxlint), format check (oxfmt), typecheck (tsc --noEmit) and `bun test` pass locally and in GitHub Actions CI on the PR.
  - `bun build --compile` produces one executable; tests start that compiled executable (not the source) with `serve --http 127.0.0.1:<free port> --dir <temp dir>` and get `GET /api/health` → 200 with upstream's JSON body `{"message":"API is healthy.","code":200,"data":{}}` (compare parsed JSON and status; note upstream's key order in the PR).
  - Each of --hooksDir, --hooksWatch, --hooksPool, --migrationsDir, --automigrate (with and without a value, before and after the command) exits non-zero with one message that names docs/design/01-scope.md; `update` does the same. The exact message text is written in 01-scope.md.
  - `serve` logs exactly one warning when pb_hooks or pb_migrations exist next to pb_data, and none otherwise.
  - Unknown paths return upstream's 404 JSON shape `{"data":{},"message":"The requested resource wasn't found.","status":404}` (verify the exact text in upstream's router/apis error code).
  - AGENTS.md "Verification" lists the exact commands (install, lint, format, typecheck, test, build) and package.json has matching scripts.
Out of scope: the router, request event, API error helpers and app context (M0.3: keep the dispatch in serve.ts minimal and obviously temporary, no generic router or registry); opening pb_data or SQLite (M0.4); the superuser part of /api/health (needs auth, M2.3; leave a header comment naming it); superuser commands (M6.2); automatic HTTPS (M6.3: accept and parse domains and --https, but serving TLS may fail with a clear "not implemented yet" error); dashboard (M6.1); upstream fetch script, Mailpit, S3 server (M0.2); differential harness (M0.5); release workflow (M7.3).
Measurements: none.
Notes from the lead:
  - No runtime dependencies in this task. Dev dependencies (typescript, @types/bun, oxlint, oxfmt, a tiny hook installer or a plain git hooks script) are fine; prefer no hook manager dependency if a few lines of script do it.
  - Flag parsing: write a small parser that follows cobra/pflag semantics for the flags in use (--flag=value, --flag value, bool flags, string slices for --origins, persistent flags before or after the command). Use node:util parseArgs only if it fits those semantics exactly; otherwise do not.
  - No process-global state: pass parsed config into serve; no module-level singletons.
  - CI: GitHub Actions on pull_request and push to main, ubuntu-latest, oven-sh/setup-bun with the Bun version pinned to the one in package.json "packageManager"/engines. Renovate config groups dev dependencies and pins actions.
