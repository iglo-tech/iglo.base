Notes from the lead:
  - Correctness and upstream behavior first; then the simplest design that keeps a slow read from stalling the event loop. A worker pool adds complexity (connection lifetime across WAL checkpoints, read-your-writes after a commit on the main thread, transactions that read and write); account for these in the decision, not only raw speed.
  - Reads inside a write transaction must stay on the transaction's connection, as upstream's nonconcurrent DB does.
  - Measure on this host but keep it light: it is a shared VM with dynamic memory and /tmp in RAM. Put generated databases inside your worktree (git-ignored) and delete them when done.
