```text
Task M0.2: Upstream reference
Goal: one command that prepares, on Linux and macOS, the pinned upstream PocketBase v0.41.0 source checkout, the pinned v0.41.0 release binary for the host, Mailpit and an S3 test server, all verified by SHA-256 and kept in a git-ignored directory, plus test helpers that start them.
Read first: AGENTS.md (Stack, Rules, Tests, Verification), docs/design/09-port-plan.md (Upstream baseline, testing sections), docs/design/12-work-plan.md (M0 rows, Rules for workers, Hard limits), docs/design/10-decisions.md (D18, D20, D21), docs/design/07-files-mail-backups-jobs.md (Tests line on Mailpit).
Upstream (v0.41.0): no Go code to port. Source: clone https://ganigeorgiev.com/git/pocketbase/pocketbase and check out f6baa0c43f379de21cd806de97ad6a2b8ca97b83 (tag v0.41.0); fail if the checked-out commit differs. Binaries: https://ganigeorgiev.com/meta/pocketbase/pocketbase/download/v0.41.0/pocketbase_0.41.0_<os>_<arch>.zip (follow redirects) for linux_amd64, linux_arm64, darwin_arm64 (the D18 platforms; add darwin_amd64 only if cheap).
Owns: test/differential/upstream.lock, scripts/upstream/ (the prepare script, in TypeScript run with Bun), test/support/ helpers that start the upstream binary, Mailpit and the S3 server, test/differential/ smoke tests, package.json scripts, .gitignore, .github/workflows/ (a job that runs the prepare command and the smoke tests on ubuntu-latest and macos-latest), the Verification section of AGENTS.md, the testing section of docs/design/09-port-plan.md if it needs the tool names, and the "until M0.2 adds the fetch script" line in docs/design/12-work-plan.md (point it at the new checkout path).
Depends on: M0.1 (merged).
Acceptance:
  - `bun run upstream:prepare` (one command) fetches into a git-ignored directory (use `.upstream/` at the repo root): the source checkout at the pinned commit, the host's pocketbase binary, Mailpit and the S3 server. Every downloaded archive is checked against the SHA-256 in test/differential/upstream.lock before it is unpacked; a mismatch fails with a clear message and leaves no half-prepared tool behind. A second run with everything present does no downloads.
  - upstream.lock is plain JSON with: upstream repo URL, tag, commit; per-platform pocketbase archive name and SHA-256; Mailpit version and per-platform archive SHA-256; S3 server version and per-platform archive SHA-256. Compute each hash by downloading the archive once; for Mailpit and versitygw also cross-check against the release's published checksums where they exist.
  - Mailpit: https://github.com/axllent/mailpit releases (v1.32.0 or the latest stable), linux amd64/arm64 and darwin arm64.
  - S3 test server: versitygw (https://github.com/versity/versitygw releases, v1.10.0 or the latest stable, Apache-2.0) with its posix backend on a temp directory. Test-only access keys are fixed dummy strings in the helper, never real credentials. If versitygw cannot serve basic PutObject/GetObject/ListObjectsV2 to Bun.S3Client, stop and report it in the PR instead of choosing another server.
  - Helpers in test/support/ start each tool on a free 127.0.0.1 port with its own temp directory and stop it cleanly: the upstream binary (`serve --http ... --dir <temp pb_data>`, wait for /api/health), Mailpit (SMTP and HTTP API ports), versitygw (posix root in a temp dir, a test bucket created).
  - Smoke tests in test/differential/ (run with `bun run test:reference`, which runs the prepare command first; plain `bun test` / `bun run check` must not need the network or .upstream): upstream binary GET /api/health → 200 with {"message":"API is healthy.","code":200,"data":{}}; one message sent over SMTP to Mailpit is read back through Mailpit's API; Bun.S3Client puts, lists and gets one object in versitygw.
  - CI: the existing check job stays; a new job runs `bun run test:reference` on ubuntu-latest and macos-latest. Cache .upstream keyed on the lock file hash if simple.
  - AGENTS.md Verification lists the new commands; docs/design/12-work-plan.md "Rules for workers" points at `.upstream/pocketbase` once prepared.
Out of scope: the differential harness and scenario format (M0.5), fixtures from tests/data (M0.5 or later), Windows, Docker (never: AGENTS.md Stack and the host rules), any change to src/.
Measurements: none.
Notes from the lead:
  - Network use is limited to GitHub and the upstream forge (ganigeorgiev.com), plus the package registry bun install already uses. No other hosts.
  - No runtime dependencies. Prefer Bun built-ins (fetch, Bun.CryptoHasher, Bun.spawn) and the system's `unzip`/`tar`; if a platform lacks one, say so in AGENTS.md.
  - Keep helpers free of process-global state: each start returns a handle with its URL/ports and a stop function.
```
