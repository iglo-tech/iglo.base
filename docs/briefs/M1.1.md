Task M1.1: Base tools
Goal: port upstream's small base packages, tools/types, tools/security (without random_by_regex.go), tools/list, tools/inflector and tools/store, to TypeScript modules under src/tools/, with upstream's unit tables ported and passing, so that the fields, settings, search and auth tasks can build on them.

Upstream (v0.41.0, .upstream/pocketbase after `bun run upstream:prepare`, or /home/t3-code/upstream/pocketbase), each with its _test.go file:
  - tools/types: datetime.go, json_raw.go, json_array.go, json_map.go, geo_point.go, types.go (Pointer has no TS counterpart; skip it and say so).
  - tools/security: crypto.go, encrypt.go, jwt.go, random.go. NOT random_by_regex.go (task M1.1a).
  - tools/list/list.go, tools/inflector/inflector.go and singularize.go, tools/store/store.go.
  Go dependencies whose behavior these files inherit, read at the exact versions in upstream's go.mod: github.com/spf13/cast v1.10.0 (cast.ToTime / StringToDate layouts and default location, used by DateTime.Scan; ToString, ToStringSlice used by list), github.com/golang-jwt/jwt/v5 v5.3.1 (parser, validator, MapClaims, signing), and the Go standard library of the toolchain the upstream binary was built with (`strings .upstream/bin/<pocketbase binary> | grep -m1 -o 'go1\.[0-9.]*'`): time (Parse/Format of the layouts used), encoding/json and encoding/json/v2 (MapClaims marshaling, json.Deterministic, string escaping, number text), crypto/cipher GCM. These are not on the host: shallow-clone them read-only from GitHub into `.upstream/deps/` inside your worktree (git-ignored); do not add them to upstream.lock or the prepare script.
Owns: src/tools/types/, src/tools/security/, src/tools/list/, src/tools/inflector/, src/tools/store/, test/tools/, and the module layout entry for src/tools/ in docs/design/02-architecture.md. File names follow upstream (src/tools/types/datetime.ts and so on), each with a header comment naming its upstream file.
Depends on: M0.1 (merged).
Acceptance:
  - Every upstream test function in the ported _test.go files is ported as a data-driven bun test under test/tools/<package>/, with upstream's cases kept (names and inputs verbatim where they have names). Cases that only test Go type mechanics with no TS counterpart (generic type parameters, nil vs empty slice where TS has one value, Pointer) are dropped and listed in the PR body with a reason.
  - DateTime: keeps Go's precision (nanoseconds; a JS Date alone loses sub-millisecond digits and must not be the only state), formats with the DefaultDateLayout "2006-01-02 15:04:05.000Z" in UTC, the zero value formats as "", and Scan/ParseDateTime accept exactly what upstream accepts (time.Parse of the default layout, then cast.ToTime's layouts and numeric Unix seconds), with the same result for the inputs in datetime_test.go plus the cast layouts you add. Time-dependent functions (NowDateTime and the like) take the clock from src/app/clock.ts; no direct Date.now() inside the module.
  - JSONRaw: text round-trips byte for byte, including integer-like object keys out of order, integers above 2^53, unusual whitespace and escapes. JSONArray, JSONMap, GeoPoint: their String/MarshalJSON/Value output is byte-identical to upstream's for the tested values (Go json v2 with Deterministic: sorted map keys, Go's escaping and number text) and Scan accepts the same inputs. Never JSON.parse + JSON.stringify where that changes bytes upstream keeps.
  - security: MD5, SHA256, SHA512, HS256, HS512, S256Challenge, Equal (constant time), Encrypt/Decrypt (AES-256-GCM, base64 of nonce||ciphertext||tag, Web Crypto) match upstream's outputs; a value encrypted by upstream's test vectors decrypts. RandomString* use a secure source and the same alphabets; Pseudorandom* may use a non-secure source as upstream does.
  - JWT with Web Crypto, no new dependency: NewJWT produces the same token bytes as golang-jwt for the same claims, key and exp (header and claims JSON exactly as Go marshals them). ParseJWT accepts only HS256 and validates exp, nbf and iat (and their types) as golang-jwt v5.3.1 does with upstream's options; ParseUnverifiedJWT validates exp, iat and nbf without the signature. Validation takes the clock from the caller. Error values may be TS-specific but the accept/reject decision must match for every case in jwt_test.go plus malformed segments, wrong alg (none, HS512), non-numeric exp, and exp exactly at now.
  - list, inflector, store: the ported tables pass. Regex patterns in these files are Go RE2; translate each one to an equivalent JS RegExp by hand (note \w, \s, case folding and Unicode differences in a comment where they matter). ExistInSliceWithRegex's list comes from internal callers only; document in the code that it takes JS RegExp syntax of the same patterns.
  - `bun run check` passes locally and in CI.
Out of scope: random_by_regex.go and any Go regexp/syntax parser (M1.1a); the record token helpers in core/record_tokens.go and Authorization loading (M2.3); settings encryption wiring (M1.3); field value normalization (M1.4); any HTTP endpoint or change to src/ outside src/tools/; any change to the shared contracts.
Measurements: none (no db, filter, realtime or file handling change).
Notes from the lead:
  - Decided by the lead (logged in docs/status.md): the base tools live in src/tools/<package>/ mirroring upstream's tools/ packages, and their ported unit tables are allowed as internal tests in test/tools/, as for the shared contracts in M0.3. These modules have no public boundary of their own; their observable behavior is covered again through the API by the tasks that use them.
  - No process-global state: tools/list and tools/inflector cache compiled patterns in upstream package variables. A module-level cache of compiled constant patterns (no per-request data) is acceptable; say so in the header comment. Anything else that holds state is created by the caller.
  - Store is upstream's generic in-memory store (used by the rate limiter, search filter cache). Port it as a class with the same methods, including SetIfLessThanLimit and its JSON marshaling; mutex semantics need no counterpart on one thread, say so.
  - src/app/clock.ts returns a Date (milliseconds). That is enough for NowDateTime; do not change the Clock contract.
  - Use Bun/Web APIs only (crypto.subtle, crypto.getRandomValues, Bun.CryptoHasher for MD5). No new runtime dependency.
