# P.11 Own JavaScript SDK

Written by the chief of staff on 2026-11-07. Owner direction (2026-11-07): "I want own the SDK, start with just copying it and adjusting to the project stack, full TypeScript coverage, auto releases on CI"; keep it in this repository; publish to npm. Read decision D36 in `docs/design/10-decisions.md` first: it is the spec. Releases are P.12, not this task.

Source: https://github.com/pocketbase/js-sdk at tag `v0.28.1` (commit `ff30f71041aeb8107001bb1ac82ad56a4fbeb93c`, MIT; about 5,100 lines in `src/`, 4,000 in `tests/`). Clone it into a `mktemp -d` directory; never port from memory. It is the version the differential SDK suite already uses.

## Scope

- **Workspace.** New `sdk/` directory, a Bun workspace of the root (`"workspaces": ["sdk"]`). `sdk/package.json`: name `iglo.base`, version `1.0.0`, `"type": "module"`, MIT, repository `iglo-tech/iglo.base` with `"directory": "sdk"`, `files` limited to the build output, README and LICENSE, no runtime dependencies, `"sideEffects": false`. Rename the private root package to `iglo.base-server`; first check that nothing reads the root package name (build script, version, Docker, workflows) and adjust what does.
- **Copy.** `src/` → `sdk/src/`, `tests/` → `sdk/tests/` (or `sdk/test/`, matching the repository). Keep upstream's file and class names for side-by-side review; each file gets a header comment naming its upstream file (`js-sdk v0.28.1 src/...`). `sdk/LICENSE` carries upstream's MIT notice (Gani Georgiev) plus iglo.base's line, like the root `LICENSE`. `sdk/README.md`: adapted from upstream's README (install `iglo.base`, `import PocketBase from "iglo.base"`, the same usage docs), with a short note that it is a fork of the PocketBase JS SDK v0.28.1 for iglo.base and also works with PocketBase v0.41.0. `sdk/CHANGELOG.md` starts at 1.0.0 ("forked from pocketbase js-sdk v0.28.1"); do not copy upstream's changelog.
- **Behavior.** No behavior change in this task: same requests, same responses, same public API and exports. Anything you think is an upstream bug goes into the PR body, not the code.
- **Build.** `sdk/scripts/build.ts` (or similar) with `Bun.build`: an ES module (`.`), CommonJS (`./cjs`) and a browser global build for `./umd` (IIFE that sets `window.PocketBase` the way upstream's UMD does for script-tag users), minified like upstream, with source maps; the `react-native` field kept. Target ES2021 output so it runs where upstream's does. Declarations with `tsc` (`emitDeclarationOnly`) so `types` resolves for every entry. Check the built package from the outside: `npm pack --dry-run` file list, an ESM import and a CJS `require` from a temporary project (Node and Bun), and the `./umd` file evaluated in a fake `window`.
- **Aliases.** AGENTS.md wants `@/` aliases and no relative imports. The root already maps `@/*` to `src/*`, so the SDK cannot reuse `@/` from the root. Pick a non-colliding alias (for example `@sdk/*` → `sdk/src/*`) that works in the root `tsconfig.json`, the SDK's own tsconfig, `bun test` and `Bun.build`, and that does not leak into the published `.d.ts` files (declarations must resolve without the alias for consumers; verify with a consumer project).
- **Types ("full TypeScript coverage").** The SDK's tsconfig uses the repository's strict settings (`strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `verbatimModuleSyntax`, `isolatedModules`) but DOM libs instead of `bun` types, since the SDK runs in browsers and Node. No `any` in `sdk/src`: turn on oxlint's `typescript/no-explicit-any` as an error for `sdk/`, replace internal `any` with `unknown`, generics or precise types. Public shapes that upstream left loose on purpose so user code compiles (for example `RecordModel`'s `[key: string]: any`, request `body`/`query` bags) keep their assignability: keep them with a lint-disable comment and a one-line reason each, and list every one in the PR body. Add type tests (a `.ts` file checked by `tsc`, using `@ts-expect-error` and an `Expect<Equal<...>>` helper) for the public generics: `collection<T>().getList/getOne/getFullList/getFirstListItem/create/update`, `authWithPassword<T>`, `send<T>`, realtime `subscribe<T>`, `batch`, the auth store models, and `ClientResponseError`.
- **Tests.** Port upstream's vitest tests to `bun test` (Sonnet subagents for the bulk). Same cases, same assertions, no tests dropped without a reason in the PR body. Bun's `mock`/`spyOn` replace `vi`. They run in the root `bun run test` (and so in `bun run check`); make sure the root `bunfig.toml` preload and ignore patterns do not break them. Run them with coverage and record the numbers in the PR body; add a coverage threshold only if the ported tests already reach it.
- **Differential suite.** `test/differential/sdk/` imports from the workspace SDK (`iglo.base`) instead of `pocketbase`; remove the `pocketbase` dev dependency. The suite must still pass against both servers. Its fetch-based EventSource shim stays in the test harness, not in the SDK.
- **Tooling.** `bun run lint`, `format:check` and `typecheck` cover `sdk/` (oxfmt formats the copied files to the repository style). `bun run check` builds the SDK too (add it to `build` or `check`; keep `dist/iglo-base` unchanged). The SDK's build output goes to `sdk/dist/` and is ignored by git. Renovate needs nothing new.
- **Docs.** Update AGENTS.md: the Stack section (the SDK in `sdk/`, npm package `iglo.base`, a second published artifact per D36; the "Do not add ... other distribution paths" line allows the SDK's npm package), the Verification list (SDK build). Update `docs/design/README.md` and `01-scope.md` where they say what the project ships, the root README's client section (use `iglo.base`, or the `pocketbase` package, both work). D36 is already written; fix it if the code has to differ, and say so in the PR.

## Out of scope

The release workflow, npm publishing and tags (P.12). New SDK features, renames or API changes. Typed collections generated from a schema.
