Task M1.8c: Record save, validate and delete
Goal: port upstream's internal record write path (no HTTP): save with validation, field interceptors and upstream's ordering, delete with relation cascade, the superuser protections and TruncateCollection, so that records written or deleted by iglo.base leave data.db exactly as upstream would and read back identically in upstream.
Read first: AGENTS.md, docs/design/12-work-plan.md (tasks M1.8a–c, M3.2, Rules for workers, Shared contracts), docs/design/02-architecture.md (records/, db/), docs/design/03-data-compatibility.md, docs/design/04-api-compatibility.md (error texts), docs/status.md (the M0.4, M1.1 (JSONRaw invalid UTF-8 written as TEXT), M1.5, M1.5b, M1.7, M1.8a and M1.8b rows and notes), docs/briefs/M1.8a.md and M1.8b.md, and the code it builds on: src/records/ (Record, record-query.ts), src/fields/ (the interceptor and validator interfaces; text, password, autodate and file Intercept behavior as far as ported), src/collections/ (collection-model.ts save path for comparison of the ordering style, collection-query.ts references), src/db/ (saveNoValidate, deleteModel, transactions, the read pool), src/validators/, src/validation/.
Upstream (v0.41.0, .upstream/pocketbase or /home/t3-code/upstream/pocketbase):
  - core/record_model.go from callFieldInterceptors to the end: callFieldInterceptors, onRecordValidate, onRecordSaveExecute (cross-collection id check, token key refresh on email/password change, interceptors around create/update execute), onRecordDeleteExecute, cascadeRecordDelete, deleteRefRecords (batch processing, required/non-required relation handling, its error texts), and the ordering that registerRecordHooks produces (model validate/create/update/delete events mapped to record events, the system hooks' priorities). There is no hook system: port the chain as direct calls in upstream's order in one saveRecord / saveRecordNoValidate / deleteRecord entry point, as M1.7 did for collections. Do not port the hook registrations in any form.
  - core/record_model_superusers.go: the protections registerSuperuserHooks installs (the last superuser cannot be deleted, superusers collection rules, and whatever else it enforces), as direct checks in the same entry points.
  - core/collection_query.go: TruncateCollection.
  - core/db.go Save/SaveNoValidate/Delete (and their Tx/Context variants as far as records need them) for the record path: validate → create/update execute, model and record error wrapping texts.
  - File field Intercept (upload, delete of replaced files) belongs to M3.2: keep its slot in the interceptor chain so M3.2 adds it without changing the order; records with files are saved with the stored names only.
  - Tests: core/record_model_test.go TestRecordValidate, TestRecordSave, TestRecordSaveIdFromOtherCollection, TestRecordSaveIdUpdateNoValidation, TestRecordSaveWithAutoTokenKeyRefresh, TestRecordDelete, TestRecordDeleteWithMultipleRelationCascade, TestRecordDeleteBatchProcessing; core/record_model_superusers_test.go; core/collection_query_test.go TestFindCollectionTruncate; the Intercept tests of the text, password and autodate fields that need a real save (TestAutodateFieldIntercept etc.) if they are pending. Records written by iglo.base read back in upstream with identical GET bodies, and `typeof()` of every column matches upstream's for the same write.
