# Brief M6.3

Written by the chief of staff on 2026-11-02 from the work plan's template. `serve` already binds `--http`; `--https` and the positional domain arguments are parsed (M0.1) but there is no TLS or certificate manager yet. The design lists `acme-client` as the ACME runtime dependency (02-architecture.md); the data directory layout has `.autocert_cache/`.

```text
Task M6.3: Automatic HTTPS (`serve example.com`)
Goal: `serve` with `--https` and/or domain arguments behaves as upstream v0.41.0: HTTPS on the main address with certificates obtained and renewed automatically through ACME (Let's Encrypt by default), the HTTP address redirecting to HTTPS and answering ACME HTTP-01 challenges, implicit www hosts with their redirect, and certificates cached in pb_data/.autocert_cache.
Read first: AGENTS.md, docs/design/01-scope.md (HTTP and CLI rows), docs/design/02-architecture.md (server/, dependencies, data directory), docs/design/03-data-compatibility.md, docs/design/04-api-compatibility.md, docs/design/10-decisions.md (D3, D22, D24, D25, D26), docs/design/12-work-plan.md (M6.3, Rules for workers), and the code it builds on: src/cli/serve.ts, src/server/serve.ts, src/apis/serve.ts (or wherever the www redirect and the banner live; M5.7 ported wwwRedirect), src/app/filesystem.ts (LocalAutocertCacheDirName or similar).
Upstream (v0.41.0, .upstream/pocketbase or /home/t3-code/upstream/pocketbase, read only): apis/serve.go (whole: address defaults, hostNames and www handling, the autocert.Manager setup, TLSConfig MinVersion and NextProtos, the HTTP redirect server via certManager.HTTPHandler, the banner's https base URL, the `:http`/`:https` fallbacks), cmd/serve.go (flags and the positional domains, the default `--http`/`--https` ports when domains are given), core (LocalAutocertCacheDirName). For the cache format and challenge order read golang.org/x/crypto/acme/autocert at the version in upstream's go.mod (v0.58.0: autocert.go, cache.go DirCache, the HTTPHandler redirect and its 302 vs. challenge answers, renewal timing) — fetch it from the Go module proxy or the upstream forge only if it is not in the Go module cache; it is the reference for behavior, not code to port line by line.
Owns: src/server/ (a new autocert module and the TLS wiring in serve), src/cli/serve.ts, the `acme-client` runtime dependency (package.json, bun.lock; it is listed in 02-architecture.md), test/server/ or test/cli/ autocert tests, test/differential/ (a new https file), test/support/ (an ACME test server helper), the pinned ACME test server in the reference tools (test/differential/upstream.lock or the reference-tools script, SHA-256 checked as the other tools), docs/design/ where they describe HTTPS.
Depends on: M0.1 (merged).
Acceptance:
  - Address and flag behavior matches upstream exactly: `serve example.com` (defaults `--http 0.0.0.0:80`, `--https 0.0.0.0:443`), explicit `--https` with and without `--http`, several domains, an explicit www domain, the implicit www hosts and their redirect, and the start banner's URL. CLI errors and output match upstream byte for byte where a test can see them.
  - With the HTTP address set, the HTTP server answers ACME HTTP-01 challenges for the whitelisted hosts and redirects every other request to HTTPS with upstream's status, Location and body (autocert's HTTPHandler). Hosts outside the whitelist get no certificate (upstream's HostPolicy error behavior).
  - Certificates are obtained on demand for whitelisted SNI names, cached, reused across restarts and renewed before expiry (autocert renews 30 days before expiry by default; test renewal with an injected clock or a short-lived test certificate, not by sleeping). TLS 1.2 minimum. The cache directory is pb_data/.autocert_cache. Data contract: aim for autocert's DirCache file format (account key file and one file per host holding the key and chain as PEM, with autocert's names) so that switching between upstream and iglo.base on the same pb_data reuses the cached certificates in both directions; test it with the upstream binary against the ACME test server. If the format cannot be matched, the PR must say why, and neither server may fail to start or corrupt the other's files because of it (then record the difference in 04-api-compatibility.md).
  - TLS-ALPN-01: upstream advertises `acme-tls/1`. If Bun.serve cannot answer TLS-ALPN-01, HTTP-01 alone is acceptable (autocert falls back to it when the HTTP handler is in use); record the difference (ports 80 and 443 both needed) in 04-api-compatibility.md. Certificates for new SNI names must be served without restarting the server (for example `server.reload` with the new TLS list, or Bun's SNI support): verify what Bun 1.4.4 offers and choose the simplest that works.
  - Tests use a local ACME test server (Pebble from GitHub releases, pinned and SHA-256 checked like the other reference tools) with its own CA trusted only by the test client; no network calls to Let's Encrypt or any other service. The suite runs in `bun run test:reference` and adds at most about 2 minutes. Unit tests for the parts that do not need the ACME server run in `bun test`.
  - No ACME or TLS work runs inside a database write transaction; certificate issuance never blocks the event loop for other requests beyond the TLS handshake waiting for its own certificate.
  - `bun run check` and `bun run test:reference` pass locally (D25). Known hardening-backlog flakes are not fixed here; list any you saw with the rerun's result.
Out of scope: custom certificates from files (upstream has no flag for it), HTTP/3, OCSP stapling, the Docker image (D3).
Measurements: none.
Notes from the lead:
  - Results are user-visible behavior: redirect status codes, Location headers, error texts and the banner must match upstream.
  - Branch: task/M6.3-autocert. PR title: "M6.3: Automatic HTTPS".
  - The host has limited memory: run `bun run check` and `bun run test:reference` one after the other, never in parallel. Bind test servers to 127.0.0.1 on free ports; never to 80/443.
  - There is no time limit; finish the task. Stop early only for a real blocker (a design conflict the lead must decide, or a usage/rate-limit error), and describe it in the PR and your reply.
```
